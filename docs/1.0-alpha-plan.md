# 1.0 Alpha Plan — UMAssisted

**Purpose**: Minimal first working build definition. This is the handoff target for starting the private implementation repository.

**Status**: Extracted directly from REQUIREMENTS.md (as of 2026-08-12). Living; update when requirements change.

## Definition (from §2)

- **1.0 alpha** = first working build.
- Incomplete voice coverage is **explicitly acceptable** (REQ-V7).
- **Alpha scope is narrowly limited to the Aoharu Hai (Unity Cup) career loop itself once a run is already in progress.** Nothing on the main menu, pre-career flows (support card selection, "Continue Career" modal, starting a new career), lobby, or non-Aoharu-Hai content is required. The only out-of-career capability needed is the ability to exit the career cleanly (e.g. Save & Exit or Give Up) and stop the assist.
- 1.0 beta hard-blocks on: full voice control of everything inside a career (REQ-V7) + progress on UI-element coverage verification (REQ-QA1).
- 1.0 final hard-blocks on: UI overlay tested against every scenario (REQ-QA2) + security architecture audit (REQ-QA3) + human/manual requirements validation pass (REQ-VAL1/REQ-VAL3). For the initial 1.0 release this explicitly includes the last two available scenarios at the time of release: **Twinkle URA Finals** and **Grand Live** (in addition to Aoharu Hai / Unity Cup coverage already exercised during development).

Alpha is deliberately the smallest slice that can demonstrate the core assistance value with real constraints (no network, named sequences only, never self-looping, never faster than best human, passive observation only during development).

## Must-Haves for Alpha (Hard)

### Sequence Priority (REQ-F5 — alpha-critical)
1. **Training auto-sweep** (REQ-A9 + REQ-A10) — highest per-turn tap volume. Hover each of Speed/Stamina/Power/Guts/Wit with human-comprehension dwell (~1.5s default, user-configurable). Same sweep toggle also arms list auto-scroll (REQ-A16) where applicable.
2. **No-choice auto-advance** (REQ-F2 + REQ-F4) — dialogue advances, result dismissals, animation skips, "Next"/"Close" flows via human-labeled generic-UI corpus entries. Ships in parallel with sweep as labels exist.
3. **Shop browse-through** (REQ-A1) — lower frequency than training; still in 1.0, after the first two are usable.

### Core Mechanism (applies from day one)
- **REQ-M1 + REQ-M3**: Android `AccessibilityService` primary path. Screen understanding via `takeScreenshot()` + ML Kit bundled OCR (REQ-M4) + fuzzy corpus match (REQ-M6). Confirmed on-device: entire client is opaque `unitySurfaceView` — accessibility node tree is useless.
- **REQ-M2**: Architectural seam for root fallback exists but is **not exercised** for alpha.
- **REQ-M5 + REQ-F4**: Offline corpus. Event text from local `master.mdb` extract (never redistributed third-party dumps). Generic-UI layer is project-maintained screenshots + human "no-choice" vs "has-choice" labels. Unmatched or unlabeled = fall through to user.
- **REQ-A1**: Only named, discrete, user-invoked sequences. No general gameplay loop.
- **REQ-A4 + REQ-A8**: Recurring decision points replay the user's prior recorded selection (opt-in per-event via A8; first occurrence always falls through). Concrete option identity is stored, not "best" judgment.
- **REQ-A5 (hard)**: Never self-loop. Every automation requires a fresh explicit user command. No timers that re-arm, no unattended loops, no "run N times".
- **REQ-A6 (hard)**: Never faster or easier than best-case able-bodied human manual play. Gesture timing, dwell, scroll pace, and reaction latency bounded by human physical limits (comprehension pacing for sweep is tighter than the A6 ceiling but still inside it).
- **REQ-A7 + REQ-A10 + REQ-V9**: Always-visible overlay kill switches (sweep on/off; voice listening on/off). Overlay for high-frequency controls; deeper config in settings screen.
- **REQ-S1 (structural)**: No `INTERNET` permission. All processing on-device. Local-only config.
- **REQ-SF1 / SF3 / SF6**: Never interfere with user input; refuse to act on foreign overlays or when target package is not foreground; act only on `com.cygames.umamusume`.
- **REQ-DEV1/DEV2/DEV3**: During development and in shipped code, agents and code never autonomously inject input against the live game. Spikes that need real `dispatchGesture` are single-button, two-step confirmed, small, staged (test target first), user-present, and uninstalled after one run.
- **REQ-P3 (distribution boundary)**: Implementation + APK are closed/private. Only top-level design docs (this repo) are public. Scaffolding the Android project, first `AccessibilityService` declaration, build files, or anything that produces an installable binary **must occur in a genuinely separate private repository**. No early public "skeleton" phase for app code.

### Voice (partial is OK for alpha)
- REQ-V1/V5/V9/V10 basics: on-device (Vosk + heed-wakeword), always-listening wake word, overlay + spoken kill switch for listening.
- Core command forms (REQ-V8/V11/V14/V15) can be partial: facility selection, ordinal + on-screen-text option picking, "gamble"/"safe"/"take the energy", race list open + scheduled/default pick.
- Full "everything inside a career" (REQ-V7) is **not** required for alpha.
- TTS readout (REQ-T1) is desirable and made more tractable by the corpus approach (text comes from the labeled entry, not live OCR), but is soft/conditional per REQ-T4.

### Validation Mindset (REQ-VAL)
- The design must remain reconcilable to REQ-VAL2 criteria (no capability beyond manual, no speed/unattended advantage, auditable, same category as TalkBack/Switch Access). The formal pass (REQ-VAL1/REQ-VAL3) is a hard blocker for 1.0 final only; not required for alpha or beta.

## Minimal Component Sketch (Architecture, Public Description)

High-level pieces that must exist for a first working build. This is *what*, not code.

1. **AccessibilityService shell** (private repo)
   - Declared in manifest (API 30+ per REQ-PL4).
   - Foreground service notification for mic when listening.
   - `onAccessibilityEvent`, `takeScreenshot()`, `dispatchGesture()` path.
   - Package guard: only act when `com.cygames.umamusume` is foreground.

2. **Screen understanding pipeline**
   - Capture → ML Kit bundled text rec (title/option regions) → fuzzy match against offline corpus (event text layer + generic-UI layer).
   - Resolution-normalized secondary visual path for low-text screens.
   - Confidence gate + explicit fall-through on no match / ambiguous.

3. **Corpus + labels (bundled, private)**
   - Event strings from local `master.mdb` extract (identity keys + dialog/option text + gamble/safe/energy tags where derivable).
   - Hand-labeled generic-UI entries (result banners, skip prompts, modals, etc.) with no-choice flags.
   - Training sweep support: facility row recognition sufficient to drive hover traversal.

4. **Named sequences (alpha slice)**
   - Training auto-sweep (REQ-A9): hover 5 facilities in order with dwell; never tap/confirm during sweep. Killable via overlay.
   - List auto-scroll (REQ-A16) when sweep toggle on (race list primary).
   - No-choice auto-advance: on match + label, dispatch the known advance/confirm gesture once, then stop.
   - Shop browse (stretch): scroll the list; do not purchase.

5. **Decision replay (REQ-A4/A8)**
   - Per (support card, event) stored selection (first occurrence never auto-fires).
   - Direct tap on an option and voice selection of the same option are equivalent for setting/updating the recorded precedent.
   - Global + per-event auto-replay toggles (default off for new recordings).
   - Visible/reviewable in settings.

6. **Overlay (REQ-A7/A10/V9)**
   - Always-visible minimal panel: sweep toggle + voice listening toggle.
   - Kill switch semantics: off state has zero residual effect on manual input.
   - Touch target sized for limited mobility; does not fight REQ-SF3 foreign detection (self-exclusion).

7. **Voice basics (partial)**
   - Wake word (heed) → Vosk command recognition.
   - Core vocabulary: facilities (with "energy" synonym for Wit), "rest", "recreation"/"date", ordinals, on-screen text, gamble/safe/take-the-energy, "race"/"just race the scheduled", start/stop listening.
   - Confirmation window (repeat = confirm) for consequential actions.
   - TTS (on-device) for choice readout where corpus text is available; short auto-replay announcement.

8. **Safety & config**
   - REQ-A12 accidental-burst detection (rate + incoherence) → offer undo where possible.
   - Local config only (export/import path later).
   - No network code paths at all.

9. **Dev/test discipline**
   - All live-game interaction during development is user-performed; tools only observe (screencap + uiautomator).
   - When real `dispatchGesture` test code is needed: single explicit button, two-step arm/fire, tiny surface, test target first, user watches, uninstall after.
